# Тесты custom-формата

```bash
python -m pytest tests/custom -q -rx
```

Цель проекта — поддерживать дампы, созданные `pg_dump` начиная с версии 15.
Проверяемая матрица сейчас охватывает версии 15–18, без сжатия и с gzip.
Матрица описывает цель совместимости; наличие `xfail` означает, что полная
поддержка соответствующего сценария ещё не реализована.

| Версия pg_dump | Версия custom-архива |
| --- | --- |
| 15 | 1.14 |
| 16 | 1.15 |
| 17 | 1.16 |
| 18 | 1.16 |

Версия архива определяется по заголовку и не равна версии сервера PostgreSQL.
При выходе новых версий `pg_dump` матрица должна расширяться реальными архивами.
Неизвестный будущий формат нельзя считать поддержанным без проверки его структуры.

Основные тесты не требуют PostgreSQL. Для независимого чтения каждого реального
архива нужен `pg_restore` той же основной версии или новее в `PATH`. Для запуска
всей матрицы достаточно `pg_restore` 18. Без подходящего инструмента пропускаются
только проверки, непосредственно вызывающие его.

На NixOS:

```bash
nix-shell -p postgresql_18 --run '.venv/bin/python -m pytest tests/custom -q -rx'
```

## Покрытие

- Независимое кодирование чисел и чанков, UTF-8, неполные данные и ошибки заголовка.
- Буферизованное чтение, bypass заголовка и чтение длинных значений.
- Передача строк через границы чанков, включая разрыв многобайтовых символов,
  пустые строки и последний фрагмент без перевода строки.
- Сравнение результата бинарных блоков с `PlainObfuscator`: без мутаций,
  обычная мутация, equal/not_equal/by_pattern, выбор из нескольких мутаций,
  UUID по source_column, JSON и NULL, удаление по комментарию и по шаблону.
- Межтабличные связи и связи колонок одной таблицы.
- Сжатая ветка: построчная обработка, несколько чанков, полнота потока
  и обязательный нулевой терминатор блока.
- Реальные заголовки и оглавления PostgreSQL 15–18, переключение контекста таблиц.
- Сквозной вызов публичного `CustomObfuscator.run` и сравнение строк, извлечённых
  через штатный `pg_restore`, с plain-результатом для исходного архива.

У тестов есть докстринги Arrange / Act / Assert. Тесты блоков устанавливают
метаданные COPY напрямую и проверяют именно `DataBlockProcessor`;
переключение таблиц самим `DumpProcessor` проверяется отдельно.
Кодирование входных чанков и декодирование результата в `helpers.py`
не используют `DumpIO`, чтобы ошибка чтения и записи не скрывалась симметричным кодом.

## Известные дефекты

Тесты ожидаемого корректного поведения помечены `xfail(strict=True)` только
для воспроизведённых ошибок. При исправлении они станут XPASS и приведут
к падению запуска, пока соответствующая метка не будет удалена.

1. `PgStageParser` сохраняет исходные строки, когда plain-парсер возвращает `None`.
2. `_process_single_line` удаляет `\n`, хотя следующий парсер ожидает границы строк;
   несколько строк склеиваются, а JSON-мутация получает невалидные данные.
3. Сжатый выходной блок не завершается нулевой длиной чанка.
4. Декомпрессия обрывается на чанке меньше 1 МиБ, не дожидаясь нулевого терминатора.
5. `BufferedStreamReader.read(size)` возвращает неполные данные для большого запроса.
6. TOC формата 1.16 содержит `relkind` между `tableam` и `owner`, а `TocParser`
   его не читает. Поле описано в [исходном коде PostgreSQL](https://github.com/postgres/postgres/blob/REL_17_STABLE/src/bin/pg_dump/pg_backup_archiver.c).

Сквозные тесты архивов PG17/18 сейчас останавливаются на ошибке TOC;
эта ошибка не относится к формату PG15/16. Сквозные проверки не подтверждают
успешность восстановления результата, пока отмечены `xfail`. Для остальных
дефектов есть отдельные проверки, не зависящие от версии TOC.
Для несжатых архивов PG15/16 есть проходящие сквозные проверки мутаций, условий,
JSON, source_column и связей; удаление проверяется отдельно и пока не работает.
Тест перехода между таблицами использует настоящие терминаторы COPY `\.`
внутри блоков и проходит. Прежний тест без терминаторов создавал неполный
синтетический поток и ошибочно относил сброс состояния к дефектам проекта.
Алгоритмы обфускации этими изменениями не исправляются. Единственное
изменение рабочего кода — исправление опечатки импорта `contstants` в `dataclasses.py`,
без которого custom-модуль не импортируется.

## Реальные тестовые архивы

В `fixtures/` сохраняются маленькие custom-дампы каждой версии PostgreSQL 15–18
из `source.sql`: `postgres<major>-z0.dump` без сжатия и `postgres<major>-z6.dump` с gzip.
Содержат только искусственные данные, пять таблиц и правила обфускации.
Проверки `test_real_fixture_is_readable` читают их напрямую через `pg_restore`,
независимо от кода проекта. Запущенный сервер для обычных тестов не нужен.

Перегенерация требует соответствующей версии PostgreSQL и запуска временного локального сервера.
Скрипт проверяет версию `pg_dump`, чтобы не выдать новый архив за созданный старой версией:

```bash
nix-shell -p postgresql_15 --run '.venv/bin/python tests/custom/generate_fixtures.py --expected-major 15'
nix-shell -p postgresql_16 --run '.venv/bin/python tests/custom/generate_fixtures.py --expected-major 16'
nix-shell -p postgresql_17 --run '.venv/bin/python tests/custom/generate_fixtures.py --expected-major 17'
nix-shell -p postgresql_18 --run '.venv/bin/python tests/custom/generate_fixtures.py --expected-major 18'
```

Скрипт создаёт временный кластер с искусственной БД, отключает TCP, использует
Unix-сокет в уникальном временном каталоге и останавливает сервер в `finally`.
Архивы могут отличаться побайтно из-за времени создания и служебных метаданных.
