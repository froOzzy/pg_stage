# Проверки plain-обфускатора на реальных дампах

Все существующие проверки plain-обфускатора и JSON-мутаций используют
сохранённый вывод настоящего `pg_dump -Fp` версий 15, 16, 17 и 18.
Одна проверка выполняется на каждой из четырёх версий через fixture `plain_dump`.
Для обычного запуска PostgreSQL устанавливать и запускать не требуется:

```bash
python -m pytest tests/test_conditions.py tests/test_prepared_data.py \
  tests/test_parse_comment_column.py tests/test_parse_comment_table.py \
  tests/test_parse_copy_values.py tests/test_json_update_mutation.py tests/plain -q
```

## Что сохранено

- equal/not_equal/by_pattern: мутация только строк, удовлетворяющих условиям.
- Разбор комментариев: добавление мутаций и таблиц удаления, игнорирование
  некорректных конфигураций, ValueError для неизвестной мутации.
- Разбор COPY: флаги `_is_data` и `_is_delete`, удаление по комментарию и шаблону.
- Удаление данных с сохранением COMMENT, COPY и терминаторов.
- Проверки email, дат, токенов, солей и значения фиксированного пароля.
- Межтабличные и внутренние связи, несколько ключей, порядок таблиц и колонок.
- Первая подходящая мутация, source_column, свежий контекст каждой строки,
  приоритет явно заданных параметров и неизменность конфигурации.
- Все прежние JSON assertions: замена, добавление, удаление, null, сохранение
  числового типа, рекурсивность и ключ `current_value`, передача current_value,
  обработка массива, скаляра и PostgreSQL NULL, ошибки JSON и неизвестной мутации.

Проверки данных вызывают публичный `PlainObfuscator.run` либо обрабатывают
полный файл построчно. Точечные проверки разбора COMMENT и COPY берут
соответствующие строки из настоящего дампа: флаги нужно проверять сразу
после заголовка COPY, до его завершения.
В JSON-тестах используется тот же Mutator, в котором тест подменяет
внутреннюю функцию для проверки передачи контекста.
Невалидный JSON хранится в текстовой колонке PostgreSQL, поэтому сам дамп
валиден, а ожидаемая ошибка возникает при обфускации.

Дополнительная проверка сравнивает весь SQL вне строк COPY: заголовки,
DDL, комментарии, настройки, `\restrict`/`\unrestrict` и границы COPY
должны оставаться без изменений.
Генератор дат в прежнем тесте мутаций получает seed 42, чтобы случайное
совпадение с исходной датой не приводило к нестабильному падению.

## Источники и перегенерация

`fixtures/pg15` … `fixtures/pg18` содержат неизменённый вывод `pg_dump`.
`helpers.py` только читает его и выделяет COPY-блоки для assertions;
тесты не подменяют строки, имена схем или комментарии внутри дампа.

`generate_fixtures.py` создаёт временный PostgreSQL-кластер без TCP,
загружает каждый сценарий в отдельную БД и запускает `pg_dump -Fp`.
Кластер останавливается и удаляется после генерации.

Исторические фрагменты `tests/sql/test_*.sql` используются только как исходные
данные для загрузки в PostgreSQL, а не как дампы при запуске тестов.
Генератор добавляет DDL, квалификацию схемы public и согласованные имена
таблиц в relations. Отсутствовавшие nullable-колонки и поля неполных строк
заполняются NULL. Новые регрессионные, JSON- и parser-сценарии задаются
в генераторе. В parser-проверках используются безопасные идентификаторы
вместо зарезервированных `table` и `column`; сохраняются проверки обеих схем
и того же состояния обфускатора.

Из корня проекта на NixOS:

```bash
nix-shell -p postgresql_15 --run '.venv/bin/python tests/plain/generate_fixtures.py --expected-major 15'
nix-shell -p postgresql_16 --run '.venv/bin/python tests/plain/generate_fixtures.py --expected-major 16'
nix-shell -p postgresql_17 --run '.venv/bin/python tests/plain/generate_fixtures.py --expected-major 17'
nix-shell -p postgresql_18 --run '.venv/bin/python tests/plain/generate_fixtures.py --expected-major 18'
```

Для одного сценария добавьте `--case original_conditions` или другое имя
файла без `.sql`; опцию можно повторять. Версия pg_dump проверяется перед
генерацией. Служебные строки и случайные ключи restrict могут отличаться
при перегенерации, поэтому побайтовая воспроизводимость файлов не ожидается.
