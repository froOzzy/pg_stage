# Проверки plain-обфускатора на реальных дампах

Все существующие проверки plain-обфускатора и JSON-мутаций используют
один общий файл `fixtures/postgres15.sql` — неизменённый вывод настоящего
`pg_dump -Fp` PostgreSQL 15. Все сценарии размещены в отдельных схемах
одной базы. Fixture `plain_dump` выбирает исходные секции нужного сценария;
каждая функциональная проверка выполняется один раз.
Для обычного запуска PostgreSQL устанавливать и запускать не требуется:

```bash
python -m pytest tests/plain -q
```

## Что сохранено

- equal/not_equal/by_pattern: мутация только строк, удовлетворяющих условиям.
- Разбор комментариев: добавление мутаций и таблиц удаления, игнорирование
  некорректных конфигураций, ValueError для неизвестной мутации.
- Разбор COPY: флаги `_is_data` и `_is_delete`, удаление по комментарию и шаблону.
- Удаление данных с сохранением COMMENT, COPY и терминаторов.
- Проверки email, дат, токенов, солей и значения фиксированного пароля.
- Межтабличные и внутренние связи, несколько ключей, порядок таблиц и колонок.
- Первая подходящая мутация, source_column, свежий контекст каждой строки,
  приоритет явно заданных параметров и неизменность конфигурации.
- Все прежние JSON assertions: замена, добавление, удаление, null, сохранение
  числового типа, рекурсивность и ключ `current_value`, передача current_value,
  обработка массива, скаляра и PostgreSQL NULL, ошибки JSON и неизвестной мутации.

Проверки данных вызывают публичный `PlainObfuscator.run` либо обрабатывают
полный файл построчно. Точечные проверки разбора COMMENT и COPY берут
соответствующие строки из настоящего дампа: флаги нужно проверять сразу
после заголовка COPY, до его завершения.
В JSON-тестах используется тот же Mutator, в котором тест подменяет
внутреннюю функцию для проверки передачи контекста.
Невалидный JSON хранится в текстовой колонке PostgreSQL, поэтому сам дамп
валиден, а ожидаемая ошибка возникает при обфускации.

Дополнительная проверка сравнивает весь SQL вне строк COPY: заголовки,
DDL, комментарии, настройки, `\restrict`/`\unrestrict` и границы COPY
должны оставаться без изменений.
Генератор дат в прежнем тесте мутаций получает seed 42, чтобы случайное
совпадение с исходной датой не приводило к нестабильному падению.

## Источники и перегенерация

`fixtures/postgres15.sql` содержит один полный дамп одной базы: все сценарии,
один заголовок и один завершающий блок `pg_dump`.
Имена схем соответствуют сценариям, например `test_equal_condition` или
`json_combined_operations`. Дополнительная схема исходного сценария называется
`<scenario>__schema`. Relations ссылаются на таблицы своего сценария.

`helpers.py` выделяет секции по исходным заголовкам `pg_dump`: CREATE SCHEMA,
TABLE, COMMENT и TABLE DATA. Выбранные секции сохраняются побайтно,
к ним добавляются исходные общий заголовок и завершающий блок.
При выборе сценария SQL, значения, комментарии и имена объектов не переписываются.
`plain_dump.table()` возвращает фактическое квалифицированное имя для assertions.

Один общий snapshot содержит и намеренно некорректные конфигурации для
негативных тестов, поэтому обработка тестами выполняется по сценариям,
а не обфускацией всего файла целиком.

Источником всех сценариев служит `fixtures/source.sql`: обычный SQL с явными
DDL, комментариями, COPY-значениями и отдельными схемами. Старые фрагменты
`tests/sql/` и Python-конструктор сценариев удалены: больше нет автоматического
дополнения пропущенных полей NULL или скрытого преобразования имён.

Общий инструмент `tools/generate_fixtures.py` создаёт временный кластер без TCP,
загружает source.sql и запускает `pg_dump -Fp`. Новый дамп сначала восстанавливается
в пустую базу; только после успеха он атомарно заменяет сохранённый snapshot.
При ошибке генерации или проверки прежний файл остаётся нетронутым.
Этот инструмент запускается разработчиком, а не pytest: обычные тесты читают
готовый дамп и не требуют сервера. `conftest.py` предоставляет pytest-фикстуры,
а не перегенерирует отслеживаемые файлы при запуске тестов.

Сценарий `typed_restore` содержит UUID, date, JSONB, numeric, PK, FK и CHECK.
`test_restore.py` обфусцирует его и восстанавливает результат в настоящий PostgreSQL,
проверяя содержимое JOIN и мутированных полей. При отсутствии серверных утилит
локально этот тест пропускается. В CI `--require-postgres` запрещает такой пропуск:

```bash
nix-shell --run 'python -m pytest --require-postgres -q'
```

Из корня проекта на NixOS:

```bash
nix-shell -p postgresql_15 --run '.venv/bin/python -m tools.generate_fixtures --format plain --expected-major 15'
```

Перед генерацией проверяется версия pg_dump: ожидается 15.
Все сценарии перегенерируются вместе, чтобы общий файл оставался настоящим
дампом одной базы, а не склейкой SQL-фрагментов.
Служебные строки и случайные ключи restrict могут отличаться при перегенерации,
поэтому побайтовая воспроизводимость файла не ожидается.

Отдельных копий plain-дампа для PG16–18 нет: в проверенных сценариях
DDL, комментарии и COPY-данные одинаковы, различаются версия в заголовке,
ключи restrict и отдельные служебные SET. Матрица бинарных архивов
`tests/custom/fixtures` остаётся отдельной и не меняется.
